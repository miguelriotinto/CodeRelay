# Patch: mouse dispatch for termlib

**Applied to** `connectbot/termlib` at the pinned commit, by
`linux-terminal/build.gradle.kts` (`patchTermlibMouse`).

**Upstream this.** termlib already exposes everything else we need; this is a
small, self-contained addition that benefits its Android consumers too, and
carrying it as a fork patch is the temporary state, not the goal.

## Why

termlib's JNI surface has `nativeDispatchKey` and `nativeDispatchCharacter` but
**no mouse function at all**. CodeRelay's own `CLAUDE.md` records the
consequence:

> Android's termlib engine takes input only from the keyboard and has no mouse
> path at all, so it still has gap (1).

"Gap (1)" is that Claude Code runs in the **alternate screen buffer**, which by
definition has no scrollback. Scrolling that transcript is not a viewport
operation — the agent must be *told* to scroll, via a wheel report. On iOS this
required hand-rolling SGR-encoded wheel events (`sendWheel(travel:at:)`) plus a
custom pan recogniser, because UIKit has no wheel event source. Android never
got a mouse path and so still cannot scroll an agent transcript at all.

On a desktop with a real scroll wheel, this is not optional.

## Why it is small

libvterm already does the hard part. It owns the current mouse mode (set by the
program via `CSI ?1000h` / `?1002h` / `?1006h` …) and encodes the report in
whatever form that mode requires — X10, SGR, urxvt. We only need to hand it the
event:

```c
void vterm_mouse_move(VTerm *vt, int row, int col, VTermModifier mod);
void vterm_mouse_button(VTerm *vt, int button, bool pressed, VTermModifier mod);
```

The generated bytes come back out through the existing `onKeyboardInput`
callback, so no new plumbing is needed on the Kotlin side beyond the declaration.

Wheel up/down are buttons **4** and **5** by X11 convention — the same encoding
the macOS client's `scrollWheel` already sends, and the one verified against a
live `claude` in a probe PTY (see `CLAUDE.md`: "SGR wheel moves the transcript,
X10 encoding / PageUp / shift+PageUp do not").

## The patch

### 1. `lib/src/main/cpp/Terminal.h`

Declare alongside the existing dispatchers (after line 62):

```cpp
    bool dispatchMouseMove(int row, int col, int modifiers);
    bool dispatchMouseButton(int button, bool pressed, int modifiers);
```

### 2. `lib/src/main/cpp/Terminal.cpp`

Implementations mirroring `dispatchKey` exactly — same lock, same null guard,
same modifier decoding:

```cpp
bool Terminal::dispatchMouseMove(int row, int col, int modifiers) {
    std::scoped_lock lock(mLock);
    if (!mVt) return false;
    VTermModifier mod = VTERM_MOD_NONE;
    if (modifiers & 1) mod = (VTermModifier)(mod | VTERM_MOD_SHIFT);
    if (modifiers & 2) mod = (VTermModifier)(mod | VTERM_MOD_ALT);
    if (modifiers & 4) mod = (VTermModifier)(mod | VTERM_MOD_CTRL);
    vterm_mouse_move(mVt, row, col, mod);
    return true;
}

bool Terminal::dispatchMouseButton(int button, bool pressed, int modifiers) {
    std::scoped_lock lock(mLock);
    if (!mVt) return false;
    VTermModifier mod = VTERM_MOD_NONE;
    if (modifiers & 1) mod = (VTermModifier)(mod | VTERM_MOD_SHIFT);
    if (modifiers & 2) mod = (VTermModifier)(mod | VTERM_MOD_ALT);
    if (modifiers & 4) mod = (VTermModifier)(mod | VTERM_MOD_CTRL);
    vterm_mouse_button(mVt, button, pressed, mod);
    return true;
}
```

And the JNI entry points, beside `nativeDispatchKey`:

```cpp
JNIEXPORT jboolean JNICALL
Java_org_connectbot_terminal_TerminalNative_nativeDispatchMouseMove(
        JNIEnv*, jobject, jlong ptr, jint row, jint col, jint modifiers) {
    return reinterpret_cast<Terminal*>(ptr)->dispatchMouseMove(row, col, modifiers);
}

JNIEXPORT jboolean JNICALL
Java_org_connectbot_terminal_TerminalNative_nativeDispatchMouseButton(
        JNIEnv*, jobject, jlong ptr, jint button, jboolean pressed, jint modifiers) {
    return reinterpret_cast<Terminal*>(ptr)->dispatchMouseButton(button, pressed, modifiers);
}
```

### 3. `lib/src/main/java/org/connectbot/terminal/TerminalNative.kt`

```kotlin
    fun dispatchMouseMove(row: Int, col: Int, modifiers: Int): Boolean {
        checkNotClosed()
        return nativeDispatchMouseMove(nativePtr, row, col, modifiers)
    }

    fun dispatchMouseButton(button: Int, pressed: Boolean, modifiers: Int): Boolean {
        checkNotClosed()
        return nativeDispatchMouseButton(nativePtr, button, pressed, modifiers)
    }

    private external fun nativeDispatchMouseMove(ptr: Long, row: Int, col: Int, modifiers: Int): Boolean
    private external fun nativeDispatchMouseButton(ptr: Long, button: Int, pressed: Boolean, modifiers: Int): Boolean
```

## Verification

`LinuxTerminalEmulatorMouseTest` asserts that with mouse reporting enabled
(`CSI ?1000h` + `CSI ?1006h`), a wheel-down dispatch produces an SGR report on
the input sink — and that with reporting **off**, it produces nothing, so a
plain shell is unaffected.
